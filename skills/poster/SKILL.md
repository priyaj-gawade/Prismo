# Strictly 3:4 Poster & Visual Composition Skill

Design a standalone, high-craft graphic poster rendered as a fixed 3:4 visual artboard (1080px × 1440px).

==================================================
D8.7 — FINAL POSTER VISUAL QUALITY POLICY
MICRO-UI / AI-SLOP / FAKE-EDITORIAL CHROME ELIMINATION
==================================================
THIS IS A HARD DESIGN CONSTRAINT.

The poster generator must create a REAL POSTER / VISUAL COMPOSITION.
It must NOT create a webpage, SaaS dashboard, documentation page, product UI, analytics screen, report, slide deck, or collection of cards that happens to have a 3:4 canvas.

A technically valid HTML/CSS document is NOT a successful poster.
VISUAL QUALITY HAS ABSOLUTE PRIORITY OVER INFORMATION DENSITY.
GENERATE A DESIGNER'S COMPOSITION, NOT A COLLECTION OF COMPONENTS.

==================================================
1. HARD MICRO-TEXT POLICY (MINIMUM 22PX)
==================================================
Posters are not UI dashboards. Do not use tiny text to create the impression of sophistication.

DEFAULT MINIMUM DESIGNED TEXT SIZE: 22px or larger at the 1080px-wide canonical artboard.

Preferred typographic scales:
- Headline / Display Title: 72px–120px+
- Major Secondary Text: 32px–48px
- Supporting Text: 24px–28px
- Captions / Metadata: 20px–24px
- Credits / Source / Legal: 16px–18px (ONLY when genuinely required, max 1 line)

STRICTLY FORBIDDEN:
- Do NOT create numerous 16px–18px labels.
- Do NOT reduce font size simply to squeeze in more information.
- Do NOT use small text as decoration.
- Do NOT use tiny text for fake technical labels, fake status indicators, fake metadata, or decorative terminology.

==================================================
2. HARD PILL / CHIP POLICY (DEFAULT 0 PILLS)
==================================================
Pills and chips are UI components. They are NOT default poster decoration.

DEFAULT: 0 PILLS.
If a pill is genuinely required by the content:
- Maximum 1 pill allowed
- Must be large enough to read effortlessly (text >= 20px)
- Must be visually subordinate and semantically meaningful
- NEVER used merely as decoration

STRICTLY FORBIDDEN:
- NEVER generate rows or pairs of pills.
- NEVER generate pills with decorative status words: `ACTIVE`, `LIVE`, `SYSTEM`, `SAFETY`, `TERM`, `LAYER`, `ENGINE`, `STATUS`.

==================================================
3. HARD STATUS-INDICATOR POLICY (ZERO STATUS DOTS)
==================================================
Do NOT use tiny:
- red dots
- green dots
- yellow dots
- blue status dots
- traffic-light indicators
- glowing status lights
- LED indicators

unless the actual subject explicitly requires a real status visualization.
- Do NOT use colored dots merely because they look "technical."
- Prohibit combinations like green dot = active, yellow dot = warning, red dot = error when fictional.
- DO NOT FABRICATE SYSTEM STATE.

==================================================
4. NO FAKE TECHNICAL UI CHROME
==================================================
For technical subjects, do NOT automatically add:
- `ACTIVE LEADER`
- `TERM 04`
- `NODE_01` / `NODE_02`
- `SYSTEM STATUS`
- `SAFETY SYSTEM`
- `STORAGE LAYER`
- `TELEMETRY`
- `ONLINE` / `PROCESSING`
- `PROTOCOL STATE`

Do not invent labels merely to make a technical poster look sophisticated.

==================================================
5. HEADER / FOOTER TEMPLATE RAIL BAN
==================================================
NO GENERIC TEMPLATE HEADER.
NO GENERIC TEMPLATE FOOTER.

Do NOT automatically generate:
- Top rail: `top-left category + top-center title + top-right label`
- Bottom rail: `bottom-left metadata + bottom-center slogan + bottom-right source`

This is an AI-generated poster cliché.
A top or bottom text element is allowed only when it has a real compositional purpose.
If removing the header/footer rail makes the poster stronger, REMOVE THEM.

==================================================
6. NO ARTIFICIAL METADATA & NO FAKE FOOTER SLOGANS
==================================================
Do NOT generate decorative metadata or fake identifiers:
- `ARCHIV 1925`
- `TERM 04`
- `SYSTEM 01`
- `VOL. 03` / `ISSUE 07`
- `LAT. 51° 50' N`
- `RFC-PROTO-9000`

Do NOT fill empty space with arbitrary footer slogans:
- `THE FUTURE OF...`
- `ENGINEERED FOR...`
- `STATE MACHINE LINEARIZABILITY`
- `DISTRIBUTED SYSTEMS`

Empty space is intentional and acceptable.

==================================================
7. PROHIBITED DEFAULT FORMULA
==================================================
DO NOT automatically generate:
  BIG TITLE
  BIG ACCENT TITLE
  PARAGRAPH
  FULL-WIDTH DARKENED IMAGE
  FOUR-COLUMN SPECIFICATION STRIP

This structure is strictly a PROHIBITED DEFAULT PATTERN.
Each poster must independently determine its title placement, image treatment, supporting copy, metadata treatment, and composition.

==================================================
8. ART DIRECTION MUST COME FIRST
==================================================
Before generating HTML/CSS, determine a visual direction:
  USER REQUEST -> SUBJECT -> CONTENT PRIORITY -> ART DIRECTION -> COMPOSITION -> TYPOGRAPHY -> HTML/CSS

Choose an art direction family appropriate to the subject:
- cinematic advertising
- editorial magazine
- luxury
- minimalist
- Swiss / grid
- brutalist
- technical schematic
- motorsport
- fashion editorial
- photographic collage
- monochrome
- typography-led
- image-led
- geometric
- documentary
- retro
- experimental

Do NOT always choose dark futuristic / SaaS aesthetics. Match palette and mood to the subject.

==================================================
9. TECHNICAL POSTERS & REAL DIAGRAMS (NOT MIND MAPS)
==================================================
TECHNICAL POSTER ≠ MIND MAP (HARD CONSTRAINT):
A technical poster is a designer's graphic composition, NOT an enterprise architecture whiteboard or mind map.

STRICTLY FORBIDDEN:
- Do NOT draw box-and-arrow constellations: [BOX] ─── [BOX] ─── [BOX].
- Do NOT repeat node cards (.node-card, .state-node, .server-box, .ui-card). Max 2 or zero!
- Do NOT place diagrams inside dark enclosed panels (.diagram-container, .hero-diagram-container). Diagrams must integrate directly into the 3:4 canvas.
- Vue Flow is strictly OPTIONAL. Use it only when graph structure or animation materially improves the concept.
- When Vue Flow or node graphs are used, NEVER use default Vue Flow classes/widgets (.vue-flow__node-default, .vue-flow__handle, .vue-flow__controls, .vue-flow__minimap). Use custom SVG or custom node styling only.

HARD TYPOGRAPHY RULE:
Technical subject does NOT imply monospace!
- Never use monospace (JetBrains Mono, Fira Code, Space Mono, Courier) for display headings or poster titles.
- Orbitron is permanently banned.
- Technical subjects should use: Neo-Grotesque (Plus Jakarta Sans, Inter), high-craft editorial serif (Fraunces, Playfair Display), or architectural condensed grotesque (Archivo Black, Bebas Neue).
- Monospace is strictly exceptional: reserved for actual syntax tokens or code lines inside <code> tags.

INSTEAD OF BOX-AND-ARROW WHITEBOARDS, USE:
- Large typographic statement with architectural scale contrast
- Monolithic visual metaphor or timeline progression
- Clean SVG relationship geometry directly woven into the artboard
- Asymmetric layout with generous intentional breathing space (30%-40%)

==================================================
10. HISTORICAL / BAUHAUS STYLE RULE
==================================================
Do NOT equate Bauhaus with a cliché checklist:
  red circle + blue rect + yellow rect + grid + black diagonal line.
Ground style in:
- proportion
- typography
- geometry
- negative space
- rhythm
- composition

Avoid turning a historical visual movement into an obvious AI cliché.

==================================================
11. AUTOMOTIVE POSTER RULE
==================================================
Automotive posters should prioritize the vehicle:
- dominant photographic subject
- dramatic crop
- cinematic composition
- strong title (>= 72px)
- restrained technical detail (large, clean, max 2 items)
- NO telemetry dashboards, NO fake KPI panels, NO tiny engineering labels, NO red dot indicators on specs.

==================================================
12. POSITIVE ART-DIRECTION REQUIREMENTS
==================================================
Every poster must intentionally establish:
1. **Clear Focal Point**: Obvious primary visual anchor. The eye must know where to go first.
2. **Dominant Scale Relationship**: At least one major visual element occupies a substantial portion of the composition.
3. **Intentional Negative Space**: Maintain 30% to 40% clean breathing room.
4. **Typographic Hierarchy**: Roman display headings (`font-style: normal`), deliberate scale contrast, minimum 22px text.
5. **Adaptive Image Relationship**: Image treatment responds to subject lighting (subtle gradient, localized scrim, vignette, duotone, or no overlay).
6. **Restrained Information Hierarchy**: Low to moderate density. Subtitles, paragraphs, and spec bars are strictly optional.

==================================================
13. COMPOSITION GRAMMAR (8 DIMENSIONS)
==================================================
Deliberately vary:
- **image_position**: full-bleed | split-left | split-right | top-hero | offset-frame | centered-subject | none
- **text_position**: top-anchored | bottom-left | center-overlaid | vertical-edge | split-column | margin-aligned
- **headline_treatment**: oversized-serif | bold-condensed | small-caps | giant-numeral | stacked-monochrome | offset-title
- **alignment_mode**: flush-left | centered | asymmetric-stagger | edge-pinned
- **density**: sparse | balanced | dense-editorial
- **information_structure**: headline-only | headline+caption | headline+minimal-specs | annotated-diagram
- **dominant_scale**: image-dominant | typography-dominant | graphic-form-dominant
- **overlay_strategy**: none | subtle-gradient | localized-scrim | soft-vignette | duotone | monochrome

==================================================
14. REGRESSION BENCHMARK FIXTURES
==================================================
- **Positive Reference**: Mustang poster, tactile architectural editorial, and clean Porsche direction (dominant imagery, large headline, focal subject, restrained info).
- **Negative Reference A (Bauhaus output)**: 3-part top archival rail, 3-part bottom rail, tiny coordinates, cliché primary shapes.
- **Negative Reference B (Generic Mind-Map Output)**: `TERM 04` with green dot, `ACTIVE LEADER` pill, `NODE_01`/`NODE_02` repeated boxed cards with connecting lines, tiny status text.

==================================================
15. POSTER ARTBOARD & SPECIFICATION
==================================================
- Strict 1080px × 1440px (3:4 ratio).
- Required root element: `<main class="poster-artboard" data-od-id="poster-root">`.
- Stable `data-od-id` attributes on all meaningful editable semantic elements:
  - `data-od-id="poster-root"`
  - `data-od-id="poster-bg"`
  - `data-od-id="headline"` (or `headline-sans` and `headline-serif` / `headline-accent`)
  - `data-od-id="supporting-copy"` (or `poster-subtext`)
  - `data-od-id="hero-image"` or `data-od-id="focal-frame"`
  - `data-od-id="diagram"` / `data-od-id="terminal-window"` / `data-od-id="media-card"`
  - `data-od-id="annotation"`
  - `data-od-id="footer-action"` / `data-od-id="source-credit"`
- Canvas background must be explicitly defined in `styles.css`.
- Pre-Emit Self-Critique Stamp: Top of `styles.css` MUST declare:
  ```css
  /* Hallmark · pre-emit critique: P5 H5 E5 S4 R5 V5 | grammar: img=[position] text=[position] type=[treatment] dominant=[scale] overlay=[strategy] */
  ```

REMOVE THE AI CHROME.
NO TINY LABELS FOR DECORATION.
NO PILLS FOR DECORATION.
NO RED/GREEN/YELLOW STATUS DOTS.
NO FAKE SYSTEM STATES.
NO GENERIC HEADER/FOOTER RAILS.

CREATE LARGE, LEGIBLE, PURPOSEFUL VISUAL ELEMENTS.
